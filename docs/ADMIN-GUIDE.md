# Руководство администратора: Authentik, справки, техподдержка

Кластер `sescserv.ru`. Команды выполняются на сервере: `ssh root@129.101.95.254`.

## 1. Как это устроено

| Сервис | Адрес | Что делает |
|---|---|---|
| **Authentik** | https://auth.sescserv.ru | Единый вход: логин и пароль для всех сервисов. |
| **Lyceum Users** (lyceum-auth) | https://api.users.sescserv.ru | База людей: ФИО, роли, класс, отделы, кто чей родитель. |
| **Справки** | https://spravki.sescserv.ru | Заказ справок учениками и родителями, выдача сотрудниками отделов. |
| **Техподдержка** | https://api.support.sescserv.ru | Заявки в техподдержку (пока только API, без сайта). |

Как это работает вместе:
1. Человек открывает справки → его перенаправляет на Authentik → он вводит логин и пароль.
2. Authentik возвращает его в сервис с токеном.
3. Сервис по токену находит человека в **Lyceum Users** и смотрит его роли и отделы.

Отсюда главное правило: **пользователей создают только через Lyceum Users** (скрипты ниже). Человек, созданный
вручную в интерфейсе Authentik, войти сможет, но справки и техподдержка его не узнают.

## 2. Служебные учётки

| Учётка | Зачем | Пароль |
|---|---|---|
| `admin` | Главный админ Lyceum Users: создаёт пользователей | `kubectl -n lyceum-auth get secret lyceum-auth-secrets -o jsonpath='{.data.ADMIN_PASSWORD}' \| base64 -d; echo` |
| `akadmin` | Админка Authentik: сброс паролей, блокировка, настройки входа | `kubectl -n authentik get secret authentik-secrets -o jsonpath='{.data.AUTHENTIK_ADMIN_PASSWORD}' \| base64 -d; echo` |

Пароли храните в менеджере паролей. Новых администраторов делайте отдельными учётками (раздел 4), а не раздавайте эти.

## 3. Регистрация и вход

- **Самостоятельной регистрации нет.** Учётки заводит администратор (раздел 4) и раздаёт логин и пароль.
- **Вход:** логин или email и пароль на странице Authentik. Если пользователь включил вторую ступень
  (приложение-аутентификатор), её тоже спросят.
- **Забыл пароль:** кнопки восстановления нет — пароль сбрасывает администратор (раздел 8).
- **Личные настройки** (2FA, смена пароля, если пункт доступен): https://auth.sescserv.ru/if/user/ → «Настройки».

## 4. Создание пользователей

### Один пользователь
```bash
bash /root/create-user.sh
```
1. Скрипт выдаст ссылку. Откройте её в браузере и войдите под `admin`.
2. Браузер откроет `https://admin.sescserv.ru/auth/callback?code=...` с ошибкой или предупреждением — это нормально.
   Скопируйте этот адрес целиком и вставьте в скрипт.
3. Ответьте на вопросы: ФИО, логин, роли, пол, класс, пароль. Можно сразу завести несколько человек.

### Сразу целую базу (CSV)
1. Подготовьте таблицу в Excel или Google Таблицах и сохраните как **CSV UTF-8, разделитель — запятая**.
   Образец: [`scripts/sescserv/users-example.csv`](../scripts/sescserv/users-example.csv).

| Колонка | Обязательно | Пример | Пояснение |
|---|---|---|---|
| `last_name`, `first_name` | да | Иванов, Иван | |
| `middle_name` | | Иванович | |
| `login` | да | ivanov | Уникальный |
| `password` | | | Пусто — пароль придумается сам |
| `roles` | да | `student` или `student;parent` | `student` `parent` `teacher` `staff` `admin` `guest` `graduate` |
| `gender` | да | `male` / `female` | |
| `grade`, `letter` | | 10, А | Класс 8–11, буква русская заглавная |
| `graduation_year` | | 2028 | |
| `birthday` | | 2010-05-12 | ГГГГ-ММ-ДД |
| `lives_in_dormitory` | | true | Живёт в общежитии |
| `departments` | | `educational_department:admin` | Отделы сотрудника, см. раздел 5 |
| `children` | | `ivanov;ivanova` | Только для родителей: логины детей |

2. Загрузите файл на сервер (с вашего ПК):
   ```bash
   scp users.csv root@129.101.95.254:/root/
   ```
3. Проверьте файл. Ничего не отправляется, скрипт только пишет ошибки по строкам:
   ```bash
   python3 /root/import-users.py /root/users.csv --check
   ```
4. Импортируйте. Вход под `admin` — так же, как в `create-user.sh`:
   ```bash
   python3 /root/import-users.py /root/users.csv
   ```
5. Логины и пароли новых пользователей скрипт сохранит в `/root/import-passwords-<дата>.csv`.
   Раздайте их и **удалите файл**.

Повторный запуск безопасен: существующих пользователей скрипт не пересоздаёт и пароли им не меняет. Отделы и
связи с детьми из файла применяются и к уже существующим пользователям.

## 5. Админы справок (кто выдаёт справки)

Справку видит и выдаёт **админ отдела**, к которому она относится. Роль `admin` в Lyceum Users для этого
не нужна — нужна позиция `admin` в отделе.

| Справка | Отдел (`departments`) | Страница для сотрудника |
|---|---|---|
| Стандартная, для военкомата, для налоговой, для соцфонда | `educational_department` | https://spravki.sescserv.ru/edu_table |
| Выдача аттестата, выдача документов | `competitive_selection_department` (ОКО) | https://spravki.sescserv.ru/csd_table |
| Общежитие | `dormitory` | https://spravki.sescserv.ru/hostel_table |

**Как назначить.** Добавьте человеку в CSV колонку `departments`, например
`educational_department:admin`. Если отделов несколько, перечислите через `;`. Запустите импорт. Для уже
существующего человека достаточно строки с его логином, ФИО, ролью и полом — заново он создан не будет.

`worker` вместо `admin` — просто участник отдела: заявки он не видит.

**Как сотрудник выдаёт справку.** Открывает страницу своего отдела → видит список заявок (номер, дата,
ученик, тип) → нажимает **«Скачать»**. Откроется готовый PDF, а заявка отметится как выданная. PDF создаётся
автоматически сразу после заявки ученика; отдельной кнопки «одобрить» нет — выдача и есть одобрение.

## 6. Техподдержка: текущее состояние

- Работает только сервер (API): https://api.support.sescserv.ru/docs. **Сайта для пользователей и сотрудников в
  кластере нет** — его нужно разработать или развернуть отдельно.
- **Ролей «админ» и «сотрудник» в техподдержке сейчас нет.** Любой вошедший пользователь может создать заявку, а
  технически и сменить статус или назначить исполнителя. Ограничивать это должен будущий сайт или доработка сервера.
- Что умеет API: создать заявку (текст и фото) в отдел, посмотреть «мои» и «назначенные мне», сменить статус
  (`not started` → `in progress` → `done`), назначить исполнителя (`worker_id` — ID человека из Lyceum Users),
  перевести в другой отдел.
- Отделы техподдержки задаются произвольными ID и не связаны с отделами из раздела 5.

**Как «создать админа техподдержки» сейчас:** завести человека (раздел 4) и, по договорённости, добавить его в
`it_department:admin`. Права это пока не даёт, но когда появятся проверки, список уже будет готов.

## 7. Как пользуются обычные пользователи

**Ученик:**
1. Открывает https://spravki.sescserv.ru и входит своим логином.
2. Выбирает вкладку отдела: учебный отдел, ОКО или общежитие.
3. Выбирает тип справки, при необходимости заполняет поля и отправляет.
4. Видит свою заявку в списке. Сотрудник отдела выдаёт справку (раздел 5).

**Родитель:** то же самое, но сначала выбирает, на кого из детей заказать справку. Дети должны быть привязаны к
родителю — колонка `children` при импорте.

**Сотрудник отдела:** входит и открывает страницу своего отдела (раздел 5).

## 8. Частые задачи

| Задача | Как |
|---|---|
| Сбросить пароль | https://auth.sescserv.ru/if/admin → Directory → Users → пользователь → «Set password» (под `akadmin`) |
| Заблокировать пользователя | Там же → «Deactivate». Данные сохранятся, войти он не сможет |
| Перевести ученика в другой класс | Сейчас только через API Lyceum Users (`PATCH /v1/users/{id}`) |
| Удалить пользователя | Через API Lyceum Users (`DELETE /v1/users/{id}`) — он удалит и из Authentik. **Не удаляйте в Authentik напрямую**: базы разойдутся. Проще заблокировать |

## 9. Известные ограничения

- На странице ученика у всех заявок отображается статус «Готово», даже если справка ещё не выдана: сервер не
  отдаёт поле `status`, которое ждёт сайт. Нужна правка в Spravki-Frontend или Spravki-Backend.
- Страница общежития (`/hostel_table`) в текущей версии сайта может отображаться без колонок.
- Веб-админки пользователей (lyceum-auth-admin) в кластере нет, поэтому создание идёт через скрипты.

Устройство кластера, развёртка, Vault, бэкапы — в [SESCSERV.md](SESCSERV.md).
